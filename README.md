# Moycraft

Moycraft — тестовое название моей воксельной 3D-песочницы на Unity.

## Первый этап: основа мира

Проект для **Unity 6000.5.0f1** с **Universal Render Pipeline 17.5.0**. Внешние ассеты и платные пакеты не требуются.

### Запуск в Unity

1. Добавьте эту папку через Unity Hub → Add project from disk.
2. После первой компиляции проект автоматически создаст и откроет сцену `Assets/Scenes/Prototype.unity`, каталог блоков и материалы. Повторно открыть её можно через **Moycraft → Create or open prototype**.
3. Нажмите **Play**, затем щёлкните по игровому окну для управления.

### Управление

| Действие | Клавиша |
|---|---|
| Движение | WASD |
| Обзор | Мышь |
| Бег | Левый Shift |
| Прыжок | Space |
| Добыча | Удерживать ЛКМ |
| Установка блока | ПКМ |
| Выбор слота | 1–9 / колёсико |
| Пауза / курсор | Esc |
| Переносной фонарь | F |

В панели есть стартовые блоки, один свободный слот и две кирки в слотах 8 и 9. Камень требует кирку первого тира. Трава даёт землю. Строить внутри персонажа нельзя; заполненная панель блокирует добычу. Нижний слой мира защищён от разрушения.

### Реализовано

- Чанки 16 × 64 × 16 и загрузка вокруг персонажа; один новый чанк за кадр.
- Одна сетка и один MeshCollider на чанк, без игрового объекта на каждый блок.
- Исключение закрытых граней, корректные стыки и отрицательные координаты.
- Генерация рельефа по seed: трава, земля, камень.
- Деревья из дерева и листвы, связанные пещеры с выходами на поверхность.
- Выбор блока прямым проходом луча через сетку, без зависимости от коллайдера чанка.
- Персонаж от первого лица с коллизиями, гравитацией, бегом и прыжком.
- Выделение блока, постепенная добыча с учётом инструмента, установка.
- Панель на 9 слотов, стаки до 64, получение и расход блоков.
- Описания всех согласованных типов блоков: `Assets/Data/Blocks`.
- Пауза и сохранение изменений в памяти при выгрузке чанков.

**Это первый этап, а не весь MVP. Сохранений на диск пока нет:** остановка Play или выход из игры удаляет изменения мира. Добавлены динамическое освещение, смена дня и ночи и переносной фонарь. Вода, лава и огонь пока описаны в каталоге, но их симуляция и размещение отключены. Лёд отображается непрозрачным, песок и гравий не падают.

### Настройка

Рендер настроен через `Assets/Settings/MoycraftURP.asset`, MSAA 4×, цветовое пространство Linear. Дневное затемнение зависит от блоков сверху и доступа к небу. Карты теней солнца выключены: дерево не отбрасывает длинную проекцию вслед за солнцем. Фонарь сохраняет собственные тени, чтобы стены перекрывали его свет.

**Moycraft → Apply URP lighting defaults** повторно применяет эти значения к текущей сцене и активным URP-профилям качества; после команды сохраните сцену. Обычное открытие проекта или **Create or open prototype** не сбрасывает ручную настройку освещения. **Moycraft → Validate URP setup** проверяет совместимость материалов, атлас, небо и источник теней. Материалы вновь создаваемого прототипа сразу используют URP; старые `Standard` и `Unlit/Color` переводятся при открытии через меню Moycraft с сохранением атласа и цвета. Рамка выделения не отбрасывает тень.

Блоки используют шейдер `Moycraft/Voxel Lit`. Всё дневное освещение ограничено доступом к небу, а рассеянная подсветка собирает вклад соседних клеток: стены поглощают свет, уменьшение проёма затемняет комнату ещё до полного закрытия. Закрытая комната без местных источников получает ноль. После установки или разрушения блока свой чанк обновляется сразу, соседние — по одному за кадр без перестроения геометрии и коллайдера. HUD остаётся видимым.

Сутки занимают 20 минут. В Play на объекте Prototype bootstrap появляется компонент DaylightCycle: Cycle Seconds задаёт длительность, Time Of Day — время (0.5 полдень, 0 полночь), Running включает ход времени. Пауза останавливает цикл. F включает и выключает переносной фонарь; он изначально выключен. Для него нужны Per Pixel и Cast Shadows в Additional Lights активного URP-профиля — в комплектном профиле они включены. Материал неба клонируется на время игры, настройки восстанавливаются после выхода из Play.

При изменении блока его чанк обновляется сразу, соседние — по одному за кадр. Пересчёт только освещения не перестраивает коллайдер. Область расчёта включает соседние чанки, их сохранённые в памяти изменения и ещё не загруженные данные генератора: свет не зависит от порядка загрузки. Дополнительное затемнение именно по высоте Y, более глубокий мир и новые пещеры остаются в следующем этапе.

Проверка независимости тени от солнца: в Play выполнить **Moycraft → Capture sun-independent shade (Play mode)**. В `Builds/RenderingReview` появятся кадры `shade-sun-east.png` и `shade-sun-west.png` с противоположными направлениями солнца. Затемнение на блоках должно совпадать; диск солнца в небе может перемещаться. Открытые грани имеют небольшую фиксированную разницу яркости: верх 1.0, бок 0.85, низ 0.70. Это сохраняет объём без тёмной стороны, поворачивающейся вслед за солнцем.

В сцене на объекте **Prototype bootstrap** задаются seed и дальность чанков. В asset каждого блока задаются постоянный ID, текстуры граней, прочность, инструмент, минимальный тир, выпадение и параметры горения. Уже используемые ID нельзя переименовывать по смыслу или назначать другим блокам после появления формата сохранений.

Тип блока занимает один байт на ячейку. Общие характеристики находятся в каталоге; изменённые ячейки хранятся отдельно. Временный прогресс добычи сбрасывается при смене цели или инструмента. Память изменений растёт с числом отредактированных ячеек; дисковое хранение и ограничение памяти относятся к следующему этапу.

### Проверки и сборка

В редакторе: **Moycraft → Run foundation checks**. Проверяются seed, отрицательные координаты, скрытые грани, стыки, коллайдеры, выгрузка/загрузка, границы мира, тировые ограничения и переполнение панели.

Проверка C# и 74 проверки чистой логики без запуска редактора (нужны установленный .NET SDK и однократный импорт URP в Unity): `./Tools/Check-Source.ps1`. Скрипт использует сборки пакетов из `Library/ScriptAssemblies`; для другой импортированной копии проекта можно передать `-PackageAssemblies <путь>`. Проверки покрывают инвентарь, инструменты, координаты, направление граней, выбор блока, генерацию, уменьшение освещения при закрытии проёмов и цикл дня; они не заменяют проверки физики и изображения в Unity.

После обновления остановите и заново запустите Play либо пересоберите приложение. Генератор версии 2 меняет рельеф для прежнего seed и добавляет деревья и пещеры. Дальность взаимодействия остаётся 5 блоков; требования к инструментам сохраняются.

Статус проверки текущего этапа описан в [docs/VALIDATION.md](docs/VALIDATION.md).

Из PowerShell в корне проекта:

```powershell
& 'C:/Program Files/Unity/Hub/Editor/6000.5.0f1/Editor/Unity.exe' -batchmode -nographics -quit -projectPath "$PWD" -executeMethod VoxelSurvival.Editor.ProjectSetup.ValidateAndBuild -logFile "$PWD/build.log"
```

Сборка создаётся в `Builds/Windows/Moycraft.exe`. Переменная окружения `VOXEL_BUILD_PATH` позволяет указать другой путь к exe. В уже открывавшемся проекте название продукта обновится после компиляции скриптов; существующий exe нужно пересобрать.

Для проверки запуска, движения, прыжка, взаимодействия и коллизий в готовой сборке:

```powershell
./Builds/Windows/Moycraft.exe -smokeTests -smokeOutput "$PWD/Builds/Smoke" -logFile "$PWD/Builds/runtime.log"
```

Проверка создаёт `runtime-results.json` и снимок `prototype.png`, затем закрывает приложение. Код выхода 0 означает успех. Автопроверки запускайте отдельно от обычной игры.
